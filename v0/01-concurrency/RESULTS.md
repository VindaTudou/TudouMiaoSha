# V0.1 丢失更新（Lost Update）

> 目的：在写任何业务代码之前，亲手看见"并发写同一个值"会出错。
> 这是秒杀超卖的**同一个 bug**，只是发生在内存里而不是数据库里。

## 实验环境

| 项 | 值 |
|---|---|
| 机器 | Apple M2，8 核，16 GB |
| JDK | Temurin 17.0.18 |
| 日期 | 2026-11-02 |
| 代码 | `NaiveCounter.java` / `AtomicCounter.java` / `SyncCounter.java` |
| 复现 | `bash run-sweep.sh` |

## 实验一：同一份工作，三种写法

100 个线程，每个线程自增 20000 次，期望结果 2,000,000。各跑 5 轮取**中位数**。

| 实现 | 实际结果 | 丢失率 | 中位耗时 | 每秒"有效"自增 |
|---|---|---|---|---|
| `NaiveCounter`（无保护） | 602,807 | **69.86%** | 11 ms | 5,480 万 |
| `AtomicCounter`（CAS） | 2,000,000 | 0% | 69 ms | 2,900 万 |
| `SyncCounter`（synchronized） | 2,000,000 | 0% | 265 ms | 754 万 |

**读法**：无保护版本"最快"，但那是因为它根本没干完活——200 万次自增只有 60 万次真正生效。
按"每秒成功自增次数"算，CAS 是锁的 3.8 倍。

## 实验二：竞争窗口越长，丢得越多

固定 100 线程，只改每个线程的自增次数：

| 每线程次数 | 中位丢失次数 | 丢失率 |
|---|---|---|
| 500 | 287 | 0.57% |
| 1,000 | 2,810 | 2.81% |
| 2,000 | 6,319 | 3.16% |
| 5,000 | 129,491 | 25.90% |
| 10,000 | 392,769 | 39.28% |
| 20,000 | 922,250 | 46.11% |
| 50,000 | 1,468,082 | 29.36% |

**读法**：并发数不变，只是让并发"持续更久"，丢失率就从 0.6% 涨到 46%。
最后一行的回落是噪声（线程完成时间被拉开，实际重叠反而变少）——这也是为什么所有数字都取中位数、跑多轮。

## 实验三：证据——`count++` 不是一步

`javap -c` 反编译 `NaiveCounter` 的自增循环：

```
7: getstatic   count   // ① 把 count 读到寄存器
10: iconst_1           // ② 常量 1
11: iadd              // ③ 相加
12: putstatic  count   // ④ 写回内存
```

这是**四条字节码、两次内存访问**。三个线程可能同时执行 ① 读到同一个值（比如 100），
然后各自加 1 写回 101 —— 三次自增，只生效一次，两次凭空消失。

## 实验四：一次失败的实验设计（要记住这个）

第一版扫描是"固定总工作量 10 万次，只改线程数"：

| 线程数 | 每线程次数 | 丢失率 |
|---|---|---|
| 10 | 10,000 | 62.9% |
| 100 | 1,000 | 3.7% |
| 400 | 250 | 0.3% |

看起来"线程越多越安全"——**结论是错的**。因为同时改了线程数和每线程次数两个变量，
真正起作用的是后者（竞争窗口长度）。这就是压测里最常见的错误：
**一次只改一个变量，否则你测出来的差异不知道该归因给谁。**

## 结论

1. `count++` 是"读-改-写"三步，并发下不是原子操作，会丢失更新。
2. 丢失率不由线程数决定，由**竞争窗口的持续时间**决定。
3. 没有保护的版本总是"最快"，因为它少干了活。**别拿错误代码的耗时当性能。**
4. 两种修法代价不同：CAS（Atomic）≈ 锁（synchronized）的 1/3.8。
5. 正确性要花钱。这个结论会在 V1-b 原样重演一次。

## 映射到项目里

| 内存版（本实验） | 数据库版（V1 会踩到） |
|---|---|
| `count++` | `SELECT stock` → 判断 → `UPDATE stock` |
| 读-改-写三步 | 查-判断-写三步 |
| 丢失更新 | **超卖** |
| `synchronized` | 行锁 / `SELECT ... FOR UPDATE` |
| `AtomicInteger` | `UPDATE ... WHERE stock >= 1`（单语句原子） |
